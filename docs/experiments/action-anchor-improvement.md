# 动作锚点改进、模型对照与能力边界

2026-11-14；无外设服务器；全部为本地录音分析、离线推理或墙钟回放。

## 结论

已修复流式文本没有进入对齐进程的问题，并增加独立的、可修订的动作起点事件。4 秒窗口、0.5 秒更新、0.25 秒尾部保留的实验配置明显改善了可用提前量，但**还不能保证“前一句开始切换、目标字开始时到位”**。开头存在双锚点到达过晚，中后段存在已经很早发布、但执行前仍发生明显修订的情况。

不能将三段录音上的高覆盖率解释成任务已通过：没有人工音素边界真值、没有实测 LLM 规划、没有机器人动作及真实 DAC 时钟。用户没有指定允许误差，本文的 100/300/500ms 只用于刻画边界，不是用户验收标准。

Qwen3-ForcedAligner 已实际安装、运行和对照。完整中文音频上的两模型起点差异通常较小，但当前 CPU 路径不足以直接替换频繁的在线调用；未来全文强塞给不完整音频会产生越界时间戳。没有测试 GPU，不据此推断其 GPU 上限。

## 代码改变

- `stepfun.py` 把 `response.audio_transcript.delta` 转发给时间戳进程，并在本地事件日志保留 delta 文本；没有保存音频 base64。
- `ResponseAlignment.set_text()` 在文本追加时保留一致的对齐前缀。末尾英文词被继续补全时，仅失效发生变化的单元及后缀。
- 新增 `alignment.starts`：只含 `index/text/text_offset/start`，不要求结束边界通过尾部检查。它与完整区间事件分别版本化、分别统计修订。
- 起点是暂定值，可能被修订或撤回；文本替换会报告失效索引。单调性不等于语音内容正确性。
- 保持实际子进程隔离、队列合并、取消过滤与故障不阻断音频。没有添加播放等待，也没有实现运动控制器。
- 在线默认仍是 6/2/1；4/.5/.25 为明确传入的实验配置。尚未将高修订配置自动设为生产默认。

63 项无硬件测试通过，包含新增流式文本、追加前缀、英文词补全、起点独立发布、撤回和事件统计检查。三段回放均完成最终修复，实际子进程取消测试通过。

## 数据与可复现边界

## 提前量：解决了多少“来得及”

以每个单元最终修复后的 start 为回顾性参照。可用余量 = 预计播放起点 + 最终 start - 首次起点事件到达时刻。

| 回复 | 首次起点事件 | 余量最小值 | 余量中位数 | 早于播放 | 余量≥300ms | 余量≥500ms | 余量≥1s |
|---|---:|---:|---:|---:|---:|---:|---:|
| 长 | 1.393s | -418ms | 7.163s | 195/197 | 193/197 | 189/197 | 184/197 |
| 短 | 0.554s | 409ms | 1.060s | 26/26 | 26/26 | 24/26 | 14/26 |
| 中 | 0.847s | 101ms | 2.640s | 104/104 | 100/104 | 94/104 | 83/104 |

上述余量不是实测 LLM 性能。它只说明假设规划、传输和安全余量总共消耗这些时间后，多少锚点尚有余量。真正 LLM 可以与对齐并行，最终受二者较晚者限制。

长回复原 6/2/1 回放完整区间为 179/197 早于预计播放，最差迟到 1.794s；此前 4/.5/.25 为 195/197、最差迟到 520ms。本次独立起点为 195/197、最差迟到 418ms。这些是不同单次回放；独立起点不是对所有字都产生改善。

独立起点有局部收益：短回复 GuideBot 的首个单元起点余量约 995ms，若等待该单元完整区间则约 269ms；中回复整体从完整区间的 102/104 提高到起点的 104/104。

合成 delta 长回复的首个起点事件在 0.582s，而真实完整文本回放是 1.393s。**只能将此视为接入增量通路的功能性观察**，不能称为真实历史提速 811ms。

## 稳定性：来得及仍可能做错时刻

| 回复 | 首次到最终 start 差异 P50 / P95 / 最大 | 最大单次 start 修订 | 完整区间合并冲突 |
|---|---:|---:|---:|
| 长 | 80 / 722 / 1520ms | 1540ms | 2 |
| 短 | 140 / 480 / 650ms | 520ms | 1 |
| 中 | 50 / 400 / 1010ms | 1180ms | 4 |

这些是同一模型的修订幅度，不是准确率。冲突的完整区间被拒绝发布并触发前缀修复；独立起点单独检查单调性、保持暂定标记。本组三段起点没有发生索引撤回，不表示今后不会撤回。

长回复复跑的首次事件 1.398s、早于播放仍为 195/197，但首次到最终 start 差异 P95 降为 324ms、最大 1000ms。合并快照和修复会受实际推理完成时刻影响；本轮不是受控负载实验，不能把两次差异全部归因于某个因素。两次结果都保留，不能只选较好的一次声称稳定。

另模拟一个可实际执行的冻结策略：每个起点假设对应一个动作，按当前预测起点提前 300ms 提交；提交前可更新，提交后不追改。按事件时间顺序模拟，不用最终边界反向挑选“最好的一版”，也不增加语音等待。该 300ms 是实验策略，不是假定下层必须用 300ms 过渡。

| 回复 | 冻结后 start 对最终 start 差异 P95 / 最大 | 差异≤100ms |
|---|---:|---:|
| 长 | 560 / 820ms | 141/197 |
| 短 | 383 / 500ms | 13/26 |
| 中 | 279 / 700ms | 76/104 |

长回复复跑的同策略 P95 为 220ms、最大 780ms，175/197 在 100ms 内。原跑与复跑的 P95 为 220～560ms，仍不支持严格百毫秒级保证。复跑产物为 `improved-starts-repeat/` 和 `action-anchor-repeat-metrics.json`。

## 双锚点比“目标字前可用”更严格

对用户例子，应在“请注意”开始前同时拿到切换开始锚点和“这”的到位锚点；到“这”前才知道它的时间可能已经来不及按原定起点开始。

录音中没有这条完全相同的例句。为量化这一差别，使用明确的替代条件：词首到位，前两个文字单元的起点开始切换。这不是语言学分词，也不是实际 LLM 规划。

| 回复与目标 | 两锚点同时就绪相对切换起点的余量 |
|---|---:|
| 长：开头创港中心 | -496ms |
| 短：创港中心 | -355ms |
| 中：创港中心 / 招商中心 | 603 / 615ms |
| 长：招商中心 / 沙盘 / 企业展示墙 | 3611 / 4913 / 4401ms |
| 中：沙盘 / 企业展示墙 | 2022 / 2628ms |

这说明开头不能保证；中后段可以获得规划空间，但仍需处理时间戳修订。若另需 300ms 的规划或传输预算，表中余量再减 300ms。无需让语音等待来补这个差额。

## Qwen3-ForcedAligner 的实测

Qwen/Qwen3-ForcedAligner-0.6B，权重下载有 SHA256 校验。qwen-asr 0.0.6、transformers 4.57.6 安装在外部 `qwen-runtime`，通过 PYTHONPATH 单独启用；没有覆盖 GuideBot 的主 transformers。推理为 CPU float32，torch 实际 2 线程；FunASR 初始化会设为 2 线程。

| 完整音频 | FunASR 推理 | Qwen 推理 | 两模型最终 start 差异 P50 / P95 / 最大 |
|---|---:|---:|---:|
| 45.48s | 1.597s | 30.020s | 50 / 130 / 170ms |
| 6.82s | 0.262s | 4.209s | 130 / 515 / 550ms |
| 22.68s | 0.734s | 11.656s | 50 / 150 / 150ms |

两模型一致不是准确率；短句英文 GuideBot 附近尤其需要人工确认。Qwen 还分别返回 2、1、1 个零长度单元，不能不加检查就当作可靠动作时刻。

短回复前缀探针：

| 只有这些音频 | 提供已完成单元的 oracle 前缀 | 提供未来完整文本 |
|---|---:|---:|
| 1.5s | 2.604s 推理 | 2.740s 推理 |
| 3s | 2.076s 推理 | 2.358s 推理 |
| 6s | 3.143s 推理 | 3.391s 推理 |

oracle 前缀由最终对齐选择，仅用于隔离推理性能，不是可部署的在线文本选择器。1.5s 音频加完整未来文本时，Qwen 为后面文字返回最高 3.68s 的 start；3s 时尾部大量堆叠在 3.04s。必须校验音频范围并拒绝这些结果，不能将“返回完整列表”算作在线成功。

同长度错误中文控制：FunASR 完整 start 最大变化 0ms；Qwen 最大变化 1760ms。这验证前者没有利用文本音素内容、后者受文本内容影响；不证明 Qwen 在正常文本下必然正确。

因此 Qwen 在当前 CPU 上保留为离线内容条件参照。若继续工程化，优先测专用 GPU 的小窗口延迟，再解决已发音文本前缀选择、重叠窗口和冻结协议；不能把 Qwen3-ASR 的流式识别接口当成流式 ForcedAligner。

## 当前方案下的整体设计建议

### 规划器使用文字引用，时间服务解析秒数

流式文本同时进入 LLM 规划器和对齐器。LLM 输出动作名、参数、切换开始与到位的文本 offset、可选持续时长，不猜测绝对秒数。重复词必须通过 response_id 和 offset 区分。位姿无需持续时长，挥手只需开放动作名和持续时长，不暴露底层轨迹。

`prepare_anchor` 和 `arrival_anchor` 是调度层概念：据用户现有能力，把解析后的切换开始与到位期限交给下层；不把过渡时间误当成挥手的持续时长，也不要求 LLM 规划关节轨迹。准确传参需在接入下层时核对实际签名。

### 调度可更新，执行一旦提交就冻结

待执行动作保存 response_id、文本版本/offset、两个锚点版本与状态。只有计划和两个必要锚点都到齐，才是可调度；已提交动作不追随未来全段修复回跳。尚未提交动作可修订，文本撤回要失效，确认打断按 response_id 取消。

令 R_plan 是计划就绪墙钟，R_start/R_arrival 是两个锚点就绪墙钟，S 是预计切换开始墙钟，J 是调度/传输余量。原定完整切换可行条件为：

`max(R_plan, R_start, R_arrival) + J <= S`

这比只要求到位前拿到 arrival 更严格。规划器和对齐器可以并行，不能把两者耗时简单相加；也不能假定音频领先量 t 永远很大。

### 迟到只降级动作

原定开始点已过、到位点未过：立即切换并保留原到位期限，使用用户下层支持的缩短过渡；是否可接受由动作约束决定。到位点已过：跳过这次强调/指向，或只保留仍有意义的后续动作。不要在目标字已经说完后补一个声称同步的指向。

开头允许不动或使用无需精确语义锚点的默认姿态。语音接收、排队和播放路径不等待规划或对齐。不要为了“稳定”引入隐藏的播放缓冲。

### 当前合理边界

当前方案适合作为**可修订、尽力同步的稀疏动作原型**，中后段具备可利用的余量；不适合作为所有句首与所有专名上百毫秒级保证的唯一时钟。单纯再缩短 step 不能消除内容无关的单元计数误差，也不能知道尚未生成音频的真实发音时间。

若后续要求更强保证，优先获取语音合成端随音频一起返回的 word/mark 时间与样本索引；若服务不支持，则考虑能暴露这些信息的 TTS 路径。它能减少事后恢复边界的问题，但在不延迟语音的前提下，仍不能保证一个晚到的 LLM 计划。若继续保留现有黑盒语音，需验证中文内容条件在线对齐与保守的提交策略，并接受开头及异常片段跳动作。

下一轮最有价值的验收数据是：带真实 delta 内容的新会话日志、少量人工标注的动作相关词首、真实规划器就绪时刻、真实下层提交/到位记录。服务器端本轮已完成可做的改进、对照和边界分析；不把缺失现场条件留给虚假的离线“通过”。
