# G1 单通道 3A 前端：研究、实验与采用方案

日期：2026-11-17。全部实验在 G1 本机 ARM CPU 离线运行，没有启动麦克风、扬声器或云端会话。
本文更新此前 `frontend-localvqe-agc2.md` 中 AGC 的配置和峰值结论，历史数据保留。

## 采用方案

当前标准前端（StepFun 与豆包）：**16 kHz 单通道 PCM → LocalVQE v1.2（AEC + NS + 去混响）→ 独立 WebRTC AGC2 → 浮点输出余量 → PCM16**。两家共用此处理链；StepFun随后重采样至24 kHz，豆包按16 kHz/20 ms/640字节上传。

- LocalVQE 保持 v1.2、2 线程、0 ms 额外参考延迟；算法内部可选输出 gate 关闭。
- 外部 RMS gate 关闭，不再把低于门限的处理后信号强行置零。
- AGC2 固定增益为 0 dB、自适应数字增益开启、最大变化 3 dB/s、初始饱和余量 24 dB、噪声增益约束 -50 dBFS。
- WebRTC 的 AEC、NS、高通、AGC1、残余回声检测均关闭，不叠加第二套降噪或去混响。
- AGC 使用浮点接口；在 PCM16 量化前保留 -1 dB 输出余量，整数保护上限为 ±29204。
- 这里的 24 dB 是**初始饱和余量**，不是目标人声 RMS；-50 dBFS 是噪声估计对增益的约束，不是背景噪声必然低于 -50 的承诺。
- SDK 播放增益与麦克风 AGC 分开；AEC 参考仍来自成功提交到 AudioClient.PlayStream 的 PCM。

决定保留 v1.2：之前本机实测 v1.3 在 2 线程下 P50 17.70 ms、P99 19.64 ms，1740/1740 帧超过 16 ms；本轮没有把它设为默认。
选择温和 AGC 的理由：默认余量 20 dB 会把部分本已合适的正常声抬高；26/30 dB 余量又会损害轻声双讲的电平。24 dB 是本轮录音与可控场景的折中，不是泛化最优解。

**尚未解决**：轻声双讲、其他游客的人声、真实展厅长混响、实际扬声器时钟偏差。没有保证所有场景的人声 RMS、SNR、ASR 或打断效果达标。

用户最终选定 v1.2 + AGC2 为 StepFun 与豆包的标准默认。归档对照包括旧 StepFun 播放期 gate、v1.3、v1.4-AEC-only，以及 −25 至 −50 dBFS 离线 gate 试听；均保留在历史实验文档和本机状态目录，不再作为默认配置。

## 官方资料核对

已直接读取[火山引擎接入必读](https://docs.volcengine.com/docs/doubao-voice/access-must-read?lang=zh)的“音频约束”，确认：

| 项目 | 推荐 | 最低准入/约束 |
| --- | --- | --- |
| 纯人声 RMS | -31.7～-23.9 dBFS，中心约 -27.6 | 不低于 -37、不高于 -19.5 dBFS |
| 峰值 | ≤ -1 dBFS | 不能仅用整段 RMS 代替峰值检查 |
| 纯背景 RMS | ≤ -50 dBFS，中心约 -52.6 | ≤ -45 dBFS |
| SNR | 20～30 dB | ≥15 dB |
| 上行 | 16 kHz、单声道、小端 int16 | 推荐20 ms，640字节，按实时节奏发送 |

官方同时说明，停止发送音频需要 mute/unmute 事件，否则可能超时；当前方案继续上传处理后的 PCM，包括静音，不因机器人播放关闭采集。
实时全双工协议参见[官方协议](https://docs.volcengine.com/docs/doubao-voice/end-to-end-real-time-voice-full-duplex-version?lang=zh)。

[LocalVQE 官方源码及说明](https://github.com/localai-org/LocalVQE)确认 v1.2/v1.3 为 AEC+NS+Dereverb 联合模型，v1.4-AEC 为只消回声的另一类模型，不能仅凭版本数字当作联合增强升级。
本机安装固定在 `7f61cd05095d42e56a135b303f5bb4d761da22b9`，官方基准是其他硬件上的模型/数据集结果，不当作本机实测。

AGC2 依据 [webrtc-audio-processing 1.3 发布源码](https://freedesktop.org/software/pulseaudio/webrtc-audio-processing/webrtc-audio-processing-1.3.tar.gz)核对：
`audio_processing.h`、`agc2/adaptive_digital_gain_applier.cc`、`agc2/agc2_common.h` 和 `agc2/limiter.cc`。
自适应增益根据语音峰值/噪声/饱和保护调节，源码初始增益8 dB、最大自适应增益30 dB、内部峰值余量1 dB；并没有暴露“-27.6 dBFS人声RMS目标”配置。
因此“打开AGC2”不等于“豆包电平合规”，限幅器也不能恢复输入中已经失真的信息。

另核对了 [RNNoise 官方说明](https://github.com/xiph/rnnoise)与 [Speex 官方手册](https://www.speex.org/docs/manual/speex-manual/node7.html)：
RNNoise 是独立 NS，无法独自替代 AEC 或处理回声参考同步；当前 LocalVQE 已有联合 NS，没有证据支持重复叠加。
Speex 提供经典 AEC/预处理/AGC，但本项目历史现场已弃用它作为在线默认；此次未恢复旧链路。
标准 WebRTC AEC3+NS+AGC2 可以作为未来整套替换的候选，**本轮没有进行该候选的音质对比，不能声称它比当前方案差**。
单通道数据不能直接开展多通道波束形成，用户已明确暂不考虑。

原文快照和实验数据均保留在仓库外 `~/.local/state/guidebot/3a-study-20261117/`；没有保存鉴权信息。

## 实验范围与方法

3 段真实会话：27.84、69.60、60.48 秒，共157.92秒：

- `realtime-1794885450517152864`
- `realtime-1794884700057828256`
- `realtime-1794538701387449792`

真实回放按记录的麦克风包、PlayStream提交/RPC返回时刻及PlayStop事件重放，只有参考已可用才交给模型，不使用未来播放信息。
旧会话有本地采样/调度差异，离线回放不能模拟前端改变后对云端回复与后续声场的闭环影响。

13 个可控合成场景，每段12秒，共156秒：
正常声、轻声、大声、中等噪声、较强噪声、正常双讲、轻声双讲、仅回声、旁人交谈、仅噪声、近端混响、双讲混响、瞬态脉冲。
近端/远端来自已保存TTS的不同片段；噪声为固定随机种子的有色噪声，回声/混响为已知FIR；不是展厅实录。
人声在3～10秒，前后留背景；纯人声示例按独立VAD选出活动样本，再调整到指定RMS。

10组AGC参数：原20 dB余量、1 dB/s慢速、噪声约束-55、22/24/26/30 dB初始余量、3/6/9 dB输出余量。
总计 **16个场景 × 10组 = 160组AGC对照**，另外保存每场景原始和不加AGC的v1.2输出。
LocalVQE输出缓存复用以隔离AGC变化；浮点峰值修复和最终仪表增加后，对全部AGC配置重新回放。

### 测量限制

- 真实录音用独立WebRTC VAD mode2在人声候选与背景候选间分段；VAD会把机器人回声、旁人也判为语音，不能将其当成目标用户的真值。
- 增加“预计播放期间”“非播放人声候选”“非播放背景候选”三种统计，但SDK没有DAC时钟，也无法仅靠它们计算真实ERLE或目标用户SNR。
- 合成输出的“人声活动时段RMS”在混合场景中仍包含残余噪声/回声/旁人，不能称为纯净人声RMS。
- 20ms帧电平分布仅作诊断；官方规范没有要求每个音素/静音过渡帧都达到推荐范围。
- 合成SI-SDR对齐只用于评估，不反馈给增强；AGC有意改变时变增益，因此SI-SDR下降不自动等价于主观质量下降。
- 数字零的RMS记为-240 dBFS计算下限，不是实际房间噪声的物理测量。
- 没有人工转写、目标人声真值、距离/角度标注，不报告未经测量的CER/WER、误打断率或大厅实测成绩。

## 电平与去噪结果

以下为已知合成人声活动时段总输出RMS（dBFS）。原AGC参数对照也已加-1 dB输出保护；不是之前达到0 dBFS的旧文件。

| 场景 | v1.2无AGC | 原20 dB余量AGC | 采用24 dB余量AGC |
| --- | ---: | ---: | ---: |
| 正常人声 | -27.43 | -22.83 | -26.63 |
| 轻声 | -35.82 | -24.15 | -27.93 |
| 大声 | -21.85 | -20.42 | -22.54 |
| 中等噪声 | -27.40 | -23.01 | -26.81 |
| 较强噪声 | -27.52 | -23.14 | -26.94 |
| 正常双讲 | -29.40 | -24.24 | -28.03 |
| 轻声双讲 | -42.48 | -31.18 | -35.18 |
| 旁人交谈 | -25.85 | -18.33 | -21.93 |
| 近端混响 | -27.11 | 见JSON | -27.10 |
| 双讲混响 | -30.23 | 见JSON | -28.84 |

正常/轻声/一般噪声/正常双讲的选定输出落在推荐范围；大声、轻声双讲、旁人交谈仍未全部落在推荐范围。
最新3段真实录音的非播放人声候选RMS，采用方案分别为 **-26.50、-30.12、-36.70 dBFS**，第三段明显偏弱。
这些数据支持把配置当作可用起点，**不支持宣称所有人声已校准到-27.6**。

去噪证据：中等有色噪声场景的SI-SDR从原始17.96到v1.2输出22.17 dB；较强噪声从9.99到15.66 dB。
只近端正常声的v1.2输出RMS变化约+0.16 dB，未靠整体静音换取上述收益。
但这是合成信号结果；对旁人交谈，v1.2的SI-SDR仅从2.09到2.16 dB，基本没有分离收益。
近端混响场景仅从8.08到9.38 dB，不能据此声称解决大厅长混响。
正常双讲从-1.93到2.99 dB；轻声双讲从-10.24到-3.59 dB，虽有改善但仍差，后接AGC无法重建已损伤的目标人声。

### 峰值与限幅

160组AGC输出全部满足峰值≤-1 dBFS，没有PCM满幅样本，最大实际峰值为-1.00015 dBFS。
增加了独立的引擎内部限幅边界计数：采用方案在最近27.84秒真实录音中仍有7个内部触边样本，其余15个场景为零。
所以本次证明的是交付PCM峰值约束，不是证明所有内部处理完全无非线性或所有可听失真都消失。
原始G1单通道可能已经过固件DSP，输入端已有失真也无法用AGC恢复。

## 完整3A链路性能

选定v1.2+AGC2连续处理12秒双讲，750个16ms hop，包含Python绑定、AGC缓冲和统计；无录放音设备：

| CPU线程 | P50/ms | P99/ms | 最慢/ms | 超16ms帧 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 9.16 | 9.48 | 10.60 | 0/750 |
| 2 | 6.38 | 8.27 | 8.77 | 0/750 |
| 4 | 4.44 | 5.76 | 51.23 | 2/750 |

4线程的均值/常见帧更快，但本轮有调度长尾且占更多CPU，保留2线程，为gesture/FunASR等预留资源。
不能从12秒样例推断严格最坏实时保证；历史v1.2长回放也有偶发超时。
AGC使用10ms块，和LocalVQE16ms、上传20ms的缓冲共同作用，新增分块等待不等于CPU耗时，不能把6.38ms当作端到端延迟。

## 代码、录音与复现

- `GuideBot/conversation/agc.py`：AGC2流式绑定、分包、峰值/能量/内部限幅统计。
- `tools/audio/agc2_bridge.cpp`：仅AGC2、浮点接口、PCM16量化前输出余量。
- `tools/audio/study_3a.py`：真实录音因果重放、13个合成场景、10组参数、独立VAD及SI-SDR诊断。
- `tools/audio/benchmark_3a.py`：完整前端1/2/4线程性能。
- 动态库及源码在 `~/.local/share/guidebot/deps/webrtc-apm/`，不放业务代码目录。
- 原始录音、192份场景输出、JSON/CSV与试听拼接在 `~/.local/state/guidebot/3a-study-20261117/`，不上传Git。
- `LISTEN.md`提供逐场景试听；`listen/*-compare.wav`顺序均为原始→v1.2无AGC→采用AGC，之间插入0.35秒静音，未分别归一化。
- 实时运行继续保存原始麦克风、LocalVQE中间音频、成功发送的最终PCM、SDK提交的回复PCM；result.json增加AGC参数及电平统计。
- 31项相关无硬件测试通过，覆盖峰值突变、静音、任意分包、参数校验、上传PCM一致性、打断、参考适配与原生LocalVQE。

```bash
conda activate GuideBot
python GuideBot/conversation/conversation.py --provider doubao
# StepFun 使用同一标准前端
python GuideBot/conversation/conversation.py --provider stepfun
# 回退旧gate方案
python GuideBot/conversation/conversation.py --provider doubao --no-agc
# 无gate、无AGC的对照
python GuideBot/conversation/conversation.py --provider doubao --no-agc --no-mic-gate
```

每次仍由用户按Enter开始/结束。回来后现场重点检查：正常声、远处轻声、播报中插话、旁人说话；目前没有远场距离和大厅录音，不自动启动采集补齐。
如果弱声双讲仍差，优先检查AEC参考时间对齐与固件音频处理；提高AGC或重新硬切gate都不能当作已验证的解决办法。
