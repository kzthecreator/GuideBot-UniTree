# Qwen3-1.7B 动作语义实验设计

状态：设计文档保留；首轮开发实验已执行，见[结果报告](../qwen-eval-results-20261125/README.md)。未改变线上提示词、通信协议或动作配置。
本实验测的是这个动作任务上的规则理解、迁移、原文定位和输出能力，不据此推断通用“智商”。

## 1. 要回答的问题

1. Qwen理解了动作含义，却因为需要同时引用文字而放弃输出吗？
2. 它是真的按动作表做判断，还是依赖present_left等熟悉英文名或记住示例？
3. 误选/漏选主要来自规则写法、正反例失衡、格式负担，还是当前1.7B非思考模式的能力限制？
4. 哪个候选在正例召回、负例误触发、引用正确和完整请求耗时之间更合适？

不预设“多加示例”“开thinking”或“拆两次请求”一定有效。
现有“合法JSON/引用26次”等数据不能作为语义准确率；上次临场调提示见过的样本只能用于开发与回归。

## 2. 数据与虚构动作

本轮已提供12项离线虚构动作、3套编号映射、64条可见开发种子。
这些是实验材料草案，尚未独立复核语义标签，不是模型测试结果或冻结盲测集。

文件：

- [fictional-actions.json](fictional-actions.json)：无轨迹、资产路径或执行绑定；所有名字只是符号。
- [id-codebooks.json](id-codebooks.json)：三套意义→不透明ID的双射。
- [development-seeds.jsonl](development-seeds.jsonl)：48条基本正反例和16条边界/干扰样本。
- [来源核对](../qwen-eval-design-sources-20261125.md)：当前软件、官方Qwen模型卡和固定llama.cpp源码依据。

### 动作分成两组

| 意义 | 虚构动作名 | 基础ID | 作用 |
| --- | --- | --- | --- |
| 开放接待/邀请提问 | 虚拟展开环 | n07 | 对应现有greet_open语义 |
| 邀请跟随 | 虚拟引路带 | q31 | 区别现在邀请与叙述别人跟随 |
| 展示左侧 | 虚拟左侧框 | m82 | 区别左侧事实与引导观察 |
| 展示右侧 | 虚拟右侧框 | v14 | 测左右对调及否定作用域 |
| 展示中央 | 虚拟中央框 | k59 | 不凭空补未知方位 |
| 暂停等待 | 虚拟暂停环 | r26 | 区别稍等、无需等待、过去等待 |
| 请求重说 | 虚拟重听环 | t93 | 区别没听清与重复播放事实 |
| 明确强调 | 虚拟重点脉冲 | z40 | 不把所有事实都当重点 |
| 明确比较两个对象 | 虚拟双卡并排 | b68 | 新定义：不等于简单出现两个名词 |
| 明确列出三个步骤/要点 | 虚拟三格点亮 | d15 | 新定义：不等于三点钟/第三个 |
| 当前结论经权威记录复核 | 虚拟实心校验印 | c74 | 新定义：区别估计、未核实、第三人称历史 |
| 当前检索未找到记录 | 虚拟空心记录印 | h22 | 新定义：区别没听清、否定“没找到” |

前8项检验熟悉语义换编号的迁移；后4项检验能否遵守新定义。
“字典规定报告无记录时输出h22”是虚构任务规则，不是要求真机做新动作。
虚构任务的显式定义优先于“普通事实通常无动作”的真实动作习惯。
后4项与真实catalog的空动作策略可能不同，两组不得直接混算准确率。

### 同一文本配不同字典

模型只看到该轮ID、说明和触发/禁止条件，不看到数据文件里的meaning、金标或real_analogue。
对相同文本分别使用：有语义名称、基础不透明ID、重排ID。
每次同步重写schema、提示示例和评分映射，不能只改一处制造无效对照。
固定少量编号方案用于成对比较，另留一套未用于调提示的方案检验迁移。
若模型一直返回空，编号不变性可能虚高，必须同时看正例召回和“重映射后仍答对”的比例。

### 代表性样本

| 原文示例 | 预期（虚构字典） | 要测什么 |
| --- | --- | --- |
| 接下来请各位把目光转向左侧的绿色材料展柜。 | 左侧框 | 正常语义与引用 |
| 左侧办公室今天的室内温度为二十四摄氏度。 | 空 | 不能见“左”就触发 |
| 暂时不要看左侧模型，下面请看右侧的航空展台。 | 仅右侧框 | 否定作用域 |
| 先前提到左侧展柜只是路线说明，最后请看左侧展柜的最新样品。 | 左侧框，目标第2次出现 | occurrence |
| 下午三点钟将有三位工作人员来到服务台。 | 空 | 不能见“三”就输出三格 |
| 接下来分为三个步骤说明：先登记，再核验，最后领取凭证。 | 三格点亮 | 学习新定义 |
| 这个时间我只是初步估计，目前尚未核实。 | 空 | 明确否定核实 |
| 接下来请看左侧的 Smart Hub 展台，了解互动方式。 | 左侧框 | 英文完整词边界 |

数据中的anchor_examples只是一个合法示例，不是唯一正确字符串。
同样自然且落在预先标注区域的其他引用也应接受；引用逐字存在、顺序和occurrence仍须严格校验。

## 3. 正式样本规模与防泄漏

建议目标为**120个场景/表达家族，每家族4个变体，共480条**：

| 分区 | 家族 | 文本 | 用途 |
| --- | --- | --- | --- |
| 开发 | 72 | 288 | 诊断、改提示、选择示例 |
| 验证 | 24 | 96 | 在已登记候选之间选优；不拿去逐句修补提示 |
| 封存测试 | 24 | 96 | 候选冻结后只跑一次用于最终比较 |

12个意义类别各设计10个家族；每类按6/2/2个家族分区。
同家族的同义改写、实体替换、否定版、引述版和最小对不能跨区。
现有线上失败、旧验收样本、提示中的10个例子及其近似改写全部登记为已见，只能进开发/回归。
本轮64条全部公开可见，因此只能作为开发种子；不是未来96条封存测试。
边界种子的家族还需补齐其余变体并满足分区配额；当前不声称已完成480条。

每家族覆盖明确正例、改写正例、词面诱导负例和作用域/边界变体；最终正负与多意图比例按真实标注统计。
主结果同时报告正负分层指标，不能依赖“总分”奖励多数类。
另外单列歧义、短到无合法引用、缺少位置上下文、超过3意图等挑战集。

金标先按动作规则独立标注，再做第二遍复核；合成规则题可程序核对，存在语义争议的样本另行裁定或移出主指标：

- 明确正例：至少必须选出哪些意义；不能用空数组算对。
- 明确负例：哪些词出现了也不能触发。
- 多解：预先写可接受动作集合和引用区域，不事后为模型答案放宽。
- 歧义：单列；金标有争议先解决或移出主指标。
- 无合法前导引用：选择能力层仍可标注意义，但联合任务允许/要求空；不能说模型“不懂欢迎”。
- 超过3意图：若实验另规定“保留最先三个”，必须明确这属于额外协议挑战，不偷换成当前生产规则。

不让被测Qwen给自己判分。人工判断可参考大模型作为辅助意见，但本方案不默认调用付费API。
如果看了封存输出再调提示，该集降为开发材料，另生成新的封存家族。

## 4. 先拆能力，再比较方法

### 第一阶段：能力定位

从开发材料固定选48条，覆盖12种意义及正反例；在真实字典和虚构字典上分别建立兼容的金标。
每个输入都使用相同原文，做三种任务：

| 任务 | 给模型什么 | 要输出什么 | 隔离什么问题 |
| --- | --- | --- | --- |
| S：只选择 | 固定动作定义+原文 | 0–3个ID | 是否理解触发/禁止语义 |
| Q：只定位 | 固定契约+人工给定正确ID+原文 | 两个引用及occurrence，或无法定位 | 会不会精确复制、找第几次及分清先后 |
| J：联合 | 固定动作定义+原文 | 当前完整动作JSON | 多任务组合是否导致全空/幻觉 |

Q里额外给正确ID是诊断用控制变量，不是把金标偷偷喂给联合任务。
若S高、Q高、J低，才有依据考虑拆任务；若S本身低，先增加引用格式例子可能治错方向。
若只改动作ID就明显崩溃，先处理字典使用和定义理解，不能称为一般“推理不行”。

先跑单字典单遍最小定位集，再扩大第二字典。按两字典×48条×3任务，上限288次调用。
该数字只是预算，不代表已经运行，也不预报耗时。

### 第二阶段：单次输入优先，逐项改变量

先在同一48条开发集上试下列候选，固定模型、量化、temperature、schema、输出上限与缓存策略。
候选是方法包；只有明确只改一个因素的成对对照才用于归因。

| 候选 | 与其直接对照的区别 | 要验证的预测 |
| --- | --- | --- |
| P0 当前生产提示 | 不变，作为基线 | 复现已知空输出和误选水平 |
| P1 结构化决策表 | 保留动作/例子内容，改为“触发→禁止→选择→引用”的分区与顺序 | 小模型是否受长散文规则位置影响 |
| P2 平衡正反例 | 在P1上替换相同数量、相近长度的例子，增加词面相同的正反最小对 | 是否降低关键词误触发及全空策略 |
| O1 短字段JSON | 同一提示策略和信息量，只缩短输出键名/嵌套，适配器还原原协议 | 输出负担是否影响正确率和完整延迟 |
| O2 两阶段 | 先选动作，再给所选ID定位；与最好的单次J比较 | 是否值得多一次串行请求的成本 |

P1不删除“禁止条件”来换取高召回。P2的例子只从开发家族选，不能把待测输入直接抄进示例。
O1须保留begin/finish各自的occurrence，不删重复短语能力，不让模型输出秒数或数文字ID。
O2第二步需要动作ID控制信息，因此属于新的通信候选；本轮只离线比较，不能自动接入生产。
两阶段最终评分必须包含第一步选错/选空的损失，不能只报给了正确ID后的引用成绩。

### 第三阶段：约束、采样和thinking对照

只在前两名上继续，避免一开始做全因素笛卡尔积。

1. 固定提示与采样，对比无grammar、JSON object、当前JSON Schema。
   所有输出均经相同评分器，格式错误保留在分母。
2. 固定提示与schema，对比当前temperature=0和官方非thinking起点：
   temperature=0.7/top_p=0.8/top_k=20/min_p=0。
3. 最后增加thinking诊断臂：官方起点0.6/0.95/20/0。
   先验证模板、reasoning/content分离及与schema的兼容，再正式计分。

官方明确不建议thinking用greedy，故不把temperature=0+thinking的异常当作该模式能力结论。
官方参数是候选起点，尚无本任务证据证明它优于当前设置。
非thinking主比较先保持384输出token上限、4K context。
额外允许1024输出token/更长超时的thinking臂，单独标为“增加资源的能力上限探针”。
需要额外context时另列，不和4K、384 token的实时可用方案混报。
长思考、截断、超时、上下文溢出分别统计，不从结果中删掉。

正温度至少3个预注册seed，淘汰差的候选后对前两名扩大到5个seed。
greedy重复3次只用于测缓存/请求顺序的稳定性，不当作3个独立语义样本。
质量实验固定缓存策略；时延实验另测冷前缀与热前缀。

## 5. 评分不能只看JSON

必须输出以下分层结果，并附每条失败原文、模型结果和错误类型：

| 指标 | 定义/防刷分 |
| --- | --- |
| 动作精确率、召回率、宏F1 | 按动作意义评分；重映射ID先还原意义；每类单独报 |
| 正例空输出率 | 必须有动作的样本被输出[]的比例；all-empty基线会直接失败 |
| 负例误触发率 | 必须无动作的样本输出任意动作的比例 |
| 动作集合完全正确率 | 接受预先定义的多解集合；不事后挑最有利解释 |
| 原文引用合法率 | 在非空预测中查逐字子串、完整词边界、occurrence和先后；空输出为N/A |
| 给定正确动作的定位成功率 | Q任务全量正确引用率；没输出也算失败 |
| 语义锚点正确率 | 引用存在之外，还必须落在对应前导/目标区域；不能引用无关的两个字凑数 |
| 联合通过率 | 同一条的动作集合、语义锚点、引用和契约全部正确；解析失败也在分母 |
| 原文覆盖与分段损失 | 全文有正确意图，但按现行10字标点分段后是否丢上下文/尾段 |
| 完整耗时/资源 | 输入、输出及reasoning tokens，完整请求时间，截断/超时，冷/热缓存 |

分母同时提供：唯一文本数、独立家族数、随机重复次数。
按家族bootstrap置信区间，不能把同一家族改写和重复请求当作独立样本放大信心。
展示all-empty、关键词匹配两个简单基线，另加真实Qwen P0。
关键词基线仅离线对照，绝不接入机器人补动作。

暂定选优门槛：明确正例召回≥90%、负例误触发≤5%、联合通过≥85%、非空引用合法≥98%，且不输出字典外动作。
这些是待实验检验的筛选目标，不是本轮达到的结果，也不是上线承诺。
按家族/动作查短板，不能用某类全空牺牲召回来压低误触发。
样本量不足时给区间而非声称“零风险”；候选差异落在统计波动内时，追加未见家族而非挑最好一轮。

## 6. 全文与流式分段必须另测

本轮64条种子既有短段，也有完整回复；不能全部直接当成生产分段输入来宣称现场效果。

- 能力层：固定完整文本，先看模型本身会不会。
- 生产契约层：使用当前next_chunk规则，“最早标点且至少10个字母/数字字符”、EOF丢不足10字符尾段、单实际请求串行。
- 同一回复比较完整文本与逐段文本，分别记录“没有可发送片段”“意义被切断”“模型明确选空”。
- 局部occurrence只能按本段计数；绑定全文时才加chunk offset，不能混成全文出现次数。
- 短到没有前导引用的样本单列，不强行拆汉字或英文词来达成任务。
- 不在实验中偷偷合并分段或添加之前的对话；若测上下文增强，必须独立登记为协议改变候选。

最后才用少量现有录制会话做离线时序回放，分别报告语义成功、时间戳可用、预算接受。
虚构动作没有录制轨迹，不给它编造物理时长/预算，不用于这一回放层。
模型语义分数不能被运动预算拒绝混淆，也不能绕过实际预算来显示“动作成功”。

## 7. 实施顺序和本轮交付边界

1. 先复核64条开发种子、12条定义和多解/短句的判分规则。
2. 冻结本机模型、源码、提示、字典和样本hash，记录完整有效采样链。
3. 做S/Q/J小规模定位，按错误分布筛提示策略；不反复盲目加例子。
4. 开发集淘汰后在验证集选出前两名，冻结最终方案，再跑封存测试。
5. 报混淆矩阵、正反例最小对、联合通过、ID重映射迁移、完整耗时与完整失败清单。
6. 若仅增加thinking/请求数才能达标，明确报告额外成本和现场适用性；若均不达标，报告能力限制，不强行填动作。

设计阶段只生成实验设计及开发草案。后续首轮执行结果见文首链接；尚未启动音频/机器人、改生产协议或推送代码。
后续实验全部是文本到JSON的离线测试；假动作永远不进入真实资产/SDK执行链路。
