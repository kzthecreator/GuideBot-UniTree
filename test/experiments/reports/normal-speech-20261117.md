# 正常音量不触发回复：录音诊断

数据：本机 `~/.local/state/guidebot/conversation/realtime-1794901057088801760`。仅离线处理，未开启麦克风、扬声器或上传重放音频。用户不记得各句音量，因此不能把特定片段认定为正常音量目标人声。

后续用户试听确认：被抑制的片段确实是“你可以帮我做什么”；这句共说三次才收到回应。因此该片段不再只是疑似噪声：已确认当前联合增强抑制了目标人声。仍未把三次提问逐句人工精确标时，不能声称三次失回应均只有同一原因。下一步应现场对照AEC-only，而非给已被抹掉的信号追加AGC增益。

## 证据与边界

- 原始麦克风约50.4秒，LocalVQE 3150帧；没有看到前端积压。当前无外部 RMS gate。
- 日志约20秒有转写暂定结果“你帮我录”，但未收到最终转写，旧终端没有显示暂定结果；不能据终端空白判断云端完全没听见。
- 日志约28.3秒的一秒窗口：原始约-31.6 dBFS，AEC输出约-99.7，上传约-98.7。显著衰减发生在LocalVQE内，而非后置AGC；此时机器人未在播放。但这尚不能证明被抑制的就是目标人声。
- 实际整轨上传RMS约-32、峰值约-4.92 dBFS，无削波；整轨含静音，不能用整轨RMS判断纯人声是否满足豆包规范。
- ASR started后PlayStop间隔约2ms，保留当前打断方案。

本轮结果 `result.json` 明确记录：LocalVQE v1.2、AGC2启用、gate关闭、SetVolume(100)成功且GetVolume读回100。故不能把这轮称为“关闭AGC”的实验。AGC整轨RMS -35.73 dBFS、峰值 -6.73 dBFS，无满幅/限幅边界样本。

- U2于27.97秒开始识别，暂定文本只有“陪伴”，之后没有completed、final或回复。
- U3于32.53秒开始识别，最终文本为“可以帮我做什？”，漏掉句首“你”和句尾“么”；34.12秒云端开始回复。
- U2与U3的麦克风录音窗口（按事件时间映射到录音包；含停顿）分别为27.97–32.53秒、32.53–34.09秒。原始/AEC/实际上传RMS分别约-34.6/-35.4/-29.2 dBFS和-35.5/-37.5/-32.6 dBFS。没有观察到上传PCM削波。前者AGC把AEC后窗口电平提高约6.2 dB，后者约4.9 dB。它们含停顿，不能当作纯人声RMS；但此轮不像单纯上传电平过低。

### v1.4-AEC 扬声器回声时序复核

复核会话 `1794905160532021120` 的离线处理。麦克风包接收时间和 `PlayStream` 参考提交时间均来自同一 `time.monotonic()` 时钟；参考PCM是SDK实际提交的16k PCM（已包含固定播放增益），按RPC完成可用时刻排序，在参考区间内保持音块连续。离线时间轴因此能复现程序记录的**软件提交时序**。

物理扬声器何时实际发声没有SDK/DAC回执，单凭软件时间无法证明声学路径零延迟。原始模型用额外参考延迟0ms。全段回放再比较50、100、150、200ms延迟，两个播报窗口的麦克风RMS变化如下（窗口包含静音）：

|参考延迟|播报1变化|播报2变化|
|---:|---:|---:|
|0 ms|-2.29 dB|-2.21 dB|
|50 ms|-2.44 dB|-1.60 dB|
|100 ms|-1.80 dB|-1.46 dB|
|150 ms|-2.20 dB|-2.54 dB|
|200 ms|-2.04 dB|-2.33 dB|

没有发现延迟扫描中有明显更有效的点；v1.4-AEC对这段现场回声的实际压制较弱，与用户听感一致。延迟扫描的PCM保存在 `~/.local/state/guidebot/conversation/realtime-1794905160532021120/v14-aec-listen/delay-sweep/`；0ms输出为同目录`v14-aec200.wav`。扬声器回声对照试听 `speaker-echo-raw-v14-aec.wav` 依次为原始/处理后的播报1、原始/处理后的播报2，段间留有静音。

如试听确认仅AEC保留了被压掉的人声，可手动做短时现场对照（仍需Enter启动）：

```bash

```

该命令只对单次进程切换模型，无NS/去混响；应比较正常说话、播放时不说话是否误触发、播放时插话。不可将其描述为已验证的完整3A替代方案。恢复默认只需不带该环境变量启动。终端现在打印实际模型名，以免AEC-only仍被误报为AEC+NS+去混响。
